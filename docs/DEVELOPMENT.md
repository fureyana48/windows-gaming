# Development & Maintenance

## Workflow

1. Review the current baseline.
2. Define the intended change.
3. Capture or verify the pre-change state.
4. Implement the change.
5. Validate the resulting state.
6. Update documentation and changelog.
7. Create a release/tag when the change represents a meaningful milestone.

## Repository Maintenance

Prefer the existing repository pattern before introducing a new directory or documentation convention. Project-specific additions are acceptable when they have a clear technical purpose.

## Quality Rules

- Do not document unverified behavior as complete.
- Keep commands and paths technically accurate.
- Avoid unnecessary duplication.
- Preserve historical records when reorganizing documentation.
